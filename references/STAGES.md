# CAMP Stages

Use [SCORE_CONTRACT.md](SCORE_CONTRACT.md) for the fixed /100 score structure. Stage and Score are related but different: Score measures five stable dimensions; Stage describes the recurring operating model actually in use.

## English

CAMP Stages are not a mandatory sequence.

**AI-driven is a diagnostic lens, not an additional Stage.** Across all Stages, ask whether the model itself is doing meaningful work and whether improvements in model capability can flow into better organizational capability through reusable context and harness.

- **Stage 0 — No AI:** almost no approved work AI.
- **Stage 1 — AI Access:** AI use exists but access/adoption is still the main constraint. Goal: practical 1 person, 1 AI access where appropriate.
- **Stage 2 — AI Workforce:** people repeatedly delegate meaningful work to general agents, beyond search, summary, or drafting.
- **Stage 3 — Connected AI:** agents repeatedly use managed internal context, governed data, enterprise tools/systems, MCP/API/connectors, permissions, triggers, or actions. Stronger evidence has owners and an operating process, not just personal scripts.
- **Stage 4 — Compounding AI:** reusable skills, sessions, decisions, corrections, metadata/context, and outcome knowledge are versioned, evaluated, distributed, and reused so future people/agents start from accumulated organizational capability.
- **Stage 5 — AI-Native Company:** work commonly starts by delegating to AI; strong employees’ capabilities are augmented and replicated, role boundaries and handoffs shrink, and R&R/team/workforce design changes around work AI can perform.

A greenfield AI-native company may start with Stage 4–5 characteristics.

### AI-facing transformation

CAMP gives stronger Agent Transformation evidence to work that makes the company **readable and executable by AI**: governed data/metadata, context, tools, MCP/API/connectors, permissions, skills, memory, actions, evals, and runtime controls.

Dashboards, portals, and workflow systems for people may still be valuable, but they do not by themselves raise Stage. Ask whether the investment expands what AI itself can understand, decide, or do.

### Operations gate

AI Operations is not a sixth score dimension, but it affects Stage confidence.

- Low-risk assistants may use lightweight controls.
- Core value-chain, customer-risk, regulated, or material write/action workflows should have repeatable quality evaluation and runtime security controls.
- Stage 4–5 should not receive High confidence if important AI failures cannot be detected or risky actions cannot be constrained.

### Agent definition

> **Agent = Model + Context + Harness**

- Model: GPT, Claude, Gemini, open-weight, proprietary model
- Context: governed data, metadata, RAG/search, documents, email/chat, memory, sessions, past decisions and outcomes
- Harness: skills, tools, MCP/API/connectors, permissions, triggers, runtime, evals, observability, security controls

### Agent test

1. Does the system naturally improve as the model improves?
2. Is current development helping AI work better through context, data, tools, skills, permissions, memory, or runtime?
3. Is the investment making work more AI-facing rather than only adding another human-facing screen or system?

If the answers are mostly No, it is usually **IT built faster with AI**, not core Agent Transformation. It may still be valuable; classify it correctly.

## 한국어

[SCORE_CONTRACT.md](SCORE_CONTRACT.md)를 고정된 100점 구조의 기준으로 사용함. Stage와 Score는 다름. Score는 고정된 5개 영역을 보고, Stage는 실제로 반복되는 Operating Model을 설명함.

CAMP Stage는 반드시 순서대로 밟는 과정이 아님.

**AI 구동형은 새로운 Stage가 아니라 진단 Lens임.** 모든 Stage에서 Model 자체가 의미 있는 일을 하는지, 그리고 Model 발전이 재사용 가능한 Context/Harness를 통해 조직 Capability 향상으로 바로 이어질 수 있는지를 봄.

- **Stage 0 — No AI:** 승인된 업무용 AI가 거의 없음.
- **Stage 1 — AI Access:** AI 사용은 시작됐지만 접근성과 보급이 여전히 가장 큰 제약임. 필요한 업무에서 실질적인 1인 1 AI 접근을 목표로 함.
- **Stage 2 — AI Workforce:** Search·요약·초안을 넘어 General Agent에게 의미 있는 실제 업무를 반복 위임함.
- **Stage 3 — Connected AI:** Agent가 관리되는 사내 Context, Data, 업무 Tool/System, MCP/API/Connector, Permission, Trigger/Action을 반복 사용함. 개인 Script보다 Owner와 운영절차가 있는 연결을 더 강한 Evidence로 봄.
- **Stage 4 — Compounding AI:** Skill, Session, 판단, 수정, Metadata/Context, 실제 결과가 Version·Eval·배포·재사용되어 다음 사람/Agent가 축적된 조직 Capability에서 시작함.
- **Stage 5 — AI-Native Company:** 일을 AI에게 먼저 위임하는 방식이 일반화되고, 잘하는 개인의 Capability가 증강·복제되며, Role Boundary/Handoff가 줄고, AI가 수행할 수 있는 일을 기준으로 R&R·Team·인력설계를 바꿈.

새로운 AI-native 조직은 처음부터 Stage 4~5 특성을 가질 수 있음.

### AI-facing Transformation

CAMP는 회사를 **AI가 읽고 실행할 수 있게 만드는 활동**을 더 강한 Agent Transformation Evidence로 봄. 예: 관리된 Data/Metadata, Context, Tool, MCP/API/Connector, Permission, Skill, Memory, Action, Eval, Runtime Control.

사람이 보는 Dashboard, Portal, Workflow System도 필요하고 가치가 있을 수 있음. 다만 그것만으로 Stage가 올라가지는 않음. 그 투자가 AI 자체가 이해·판단·실행할 수 있는 범위를 넓히는지 봄.

### Operations Gate

AI Operations는 여섯 번째 점수영역은 아니지만 Stage Confidence에 영향을 줌.

- 저위험 Assistant는 가벼운 Control을 사용할 수 있음.
- Core Value Chain, 고객위험, 규제업무, 중요한 Write/Action Workflow에는 반복 가능한 품질 Eval과 Runtime Security Control이 필요함.
- 중요한 AI 실패를 발견할 수 없거나 위험한 Action을 제한할 수 없다면 Stage 4–5를 High Confidence로 부여하지 않음.

### Agent 정의

> **Agent = Model + Context + Harness**

- Model: GPT, Claude, Gemini, Open-weight, 자체 모델
- Context: 관리되는 Data, Metadata, RAG/Search, 문서, Email/Chat, Memory, Session, 과거 판단과 결과
- Harness: Skill, Tool, MCP/API/Connector, Permission, Trigger, Runtime, Eval, Observability, Security Control

### Agent Test

1. 모델이 좋아질수록 시스템도 자연스럽게 좋아지는가?
2. 현재 개발이 Context, Data, Tool, Skill, Permission, Memory, Runtime을 통해 AI가 더 잘 일하게 하는가?
3. 사람용 화면/시스템을 하나 더 만드는 것을 넘어 업무를 AI-facing으로 만드는가?

대부분 No라면 대개 **AI로 더 빨리 만든 기존 IT**이며 Core Agent Transformation과는 구분함. 가치가 없다는 뜻은 아니며 정확히 분류하는 것이 중요함.
