# CAMP Stages

## English

CAMP Stages describe the organization’s **current recurring operating model**, not a mandatory sequence.

- **Stage 0 — No AI:** almost no approved work AI.
- **Stage 1 — AI Access:** AI is limited to some users/functions. Goal: 1 person, 1 AI.
- **Stage 2 — AI Workforce:** people regularly delegate real work to general agents.
- **Stage 3 — Connected AI:** agents use internal RAG, data, MCP/API, enterprise systems, permissions, triggers, or schedulers.
- **Stage 4 — Compounding AI:** skills, sessions, decisions, and context become reusable organizational assets.
- **Stage 5 — AI-Native Company:** work starts agent-first; roles broaden, handoffs shrink, and organization design changes around AI.

A greenfield AI-native company may start with Stage 4–5 characteristics.

### Agent definition

> **Agent = Model + Context + Harness**

- Model: GPT, Claude, Gemini, open-weight, proprietary model
- Context: data, RAG, documents, email/chat, memory, sessions, past decisions
- Harness: skills, tools, MCP/API, permissions, triggers, runtime, evals, observability

### Agent test

1. Does the system naturally improve as the model improves?
2. Is current development helping the AI work better through context, tools, skills, permissions, or runtime?

If both answers are No, it is usually **IT built faster with AI**, not core Agent Transformation.

## 한국어

CAMP Stage는 반드시 순서대로 밟는 과정이 아니라, 조직의 **현재 반복적 Operating Model**을 나타냅니다.

- **Stage 0 — No AI:** 승인된 업무용 AI가 거의 없음.
- **Stage 1 — AI Access:** 일부 사용자/기능만 AI 사용. 목표는 1인 1 AI.
- **Stage 2 — AI Workforce:** 개인이 General Agent에게 실제 업무를 반복 위임.
- **Stage 3 — Connected AI:** Agent가 사내 RAG, Data, MCP/API, 업무시스템, 권한, Trigger/Scheduler를 사용.
- **Stage 4 — Compounding AI:** Skill, Session, 판단, Context가 조직 자산으로 축적·재사용.
- **Stage 5 — AI-Native Company:** Agent-first로 일하고 역할이 넓어지며 Handoff와 조직 경계가 줄어듦.

새로운 AI-native 조직은 처음부터 Stage 4~5 특성을 가질 수 있습니다.

### Agent 정의

> **Agent = Model + Context + Harness**

- Model: GPT, Claude, Gemini, open-weight, 자체 모델
- Context: Data, RAG, 문서, Email/Chat, Memory, Session, 과거 의사결정
- Harness: Skill, Tool, MCP/API, Permission, Trigger, Runtime, Eval, Observability

### Agent Test

1. 모델이 좋아질수록 시스템도 자연스럽게 좋아지는가?
2. 현재 개발이 Context, Tool, Skill, Permission, Runtime을 통해 AI가 더 잘 일하게 하는가?

둘 다 No라면 대개 **AI로 더 빨리 만든 기존 IT**이며, 핵심 Agent Transformation과는 구분합니다.
